**Data model.** One record per adaptation at `datasets/adaptations/<id>.md` — YAML frontmatter + free body. The **manifest is the single source of truth** for artifact membership; `is_live(surface, ref)` consults it.

```yaml

name: "Stock sentinel"
claude_session_id: "5f0e...-uuid"
state: building        # building | off | on
created: "2026-06-12T18:30:00Z"
status: active         # active | deleted
manifest:
  - {surface: adapter,   ref: "ecommerce/shopify",            commit: "abc123"}
  - {surface: worker,    ref: "scripts/workers/stock_sentinel.md", commit: "def456"}
  - {surface: card-type, ref: "stock-alert",                  commit: "def456"}
---
(human notes)
```

**Liveness rule:** `is_live(surface, ref)` → if some non-deleted adaptation's manifest owns `(surface, ref)`, return `state == "on"`; if no adaptation owns it, return `True` (unowned/legacy artifacts are always live — back-compat).

## Phase 3 — survive-disconnect run substrate (shared)

### Task 5: `live_runs` — run-to-log + tail-log, decoupled from any connection

**Files:** Create `scripts/live_runs.py`; test `tests/test_live_runs.py`.

**The insight:** a background daemon thread fully consumes the runner generator and appends each event to a persisted log; the SSE endpoint only *tails* the log. Because the SSE handler no longer owns the generator, a client disconnect cannot close it — so `_spawn`'s process-group kill never fires on disconnect, and **the build survives**.

**API:**
- `start(key, source_iter, append_fn) -> None` — if a run for `key` is already live, no-op. Else spawn a daemon thread that iterates `source_iter`, calling `append_fn(event)` per event and notifying waiters; on completion (or exception) mark the run done (store any error). 
- `is_live(key) -> bool`.
- `tail(key, read_fn, heartbeat=15.0) -> generator` — yield `{"kind":"_replay", ...}`-stripped events: first replay everything `read_fn()` returns, then block on a `threading.Condition` for new events (re-read `read_fn()` past the last index), emitting `{"kind":"heartbeat"}` every `heartbeat` seconds of silence, until the run is marked done AND the log is fully drained. A closed/`GeneratorExit` tail must NOT affect the source thread.

**Step 1: Failing tests.**

```python
import threading, time, itertools
import live_runs

def test_source_runs_to_completion_with_no_tail(monkeypatch):
    log = []
    src = iter([{"n": 1}, {"n": 2}, {"n": 3}])
    live_runs.start("k1", src, log.append)
    deadline = time.time() + 2
    while live_runs.is_live("k1") and time.time() < deadline:
        time.sleep(0.01)
    assert log == [{"n": 1}, {"n": 2}, {"n": 3}]
    assert not live_runs.is_live("k1")

def test_tail_replays_then_streams(monkeypatch):
    log = []
    gate = threading.Event()
    def src():
        yield {"n": 1}
        gate.wait(1)
        yield {"n": 2}
    live_runs.start("k2", src(), log.append)
    seen = []
    t = live_runs.tail("k2", lambda: list(log), heartbeat=0.05)
    seen.append(next(e for e in t if e.get("kind") != "heartbeat"))  # {"n":1}
    gate.set()
    for e in t:
        if e.get("kind") == "heartbeat":
            continue
        seen.append(e)
    assert {"n": 1} in seen and {"n": 2} in seen

def test_closing_tail_does_not_kill_source():
    log = []
    go = threading.Event()
    def src():
        yield {"n": 1}
        go.wait(1)
        yield {"n": 2}
    live_runs.start("k3", src(), log.append)
    t = live_runs.tail("k3", lambda: list(log), heartbeat=0.05)
    next(t)            # consume one
    t.close()          # simulate client disconnect
    go.set()
    deadline = time.time() + 2
    while live_runs.is_live("k3") and time.time() < deadline:
        time.sleep(0.01)
    assert log == [{"n": 1}, {"n": 2}]   # source completed despite closed tail
```

Use `platform_lib` for nothing here (pure threading/stdlib — keep it portable; no signals). Heartbeats via `condition.wait(timeout=heartbeat)`.

### Task 9: `adapt_runner` — drive the gated build session, capture the manifest

**Files:** Create `scripts/adapt_runner.py`; test `tests/test_adapt_runner.py`. Reuse `chat_runner.build_chat_cmd`, `chat_runner.normalize`, `chat_runner._spawn`.

**Behavior of `run_turn(adaptation_id, message)` (generator, yields normalized events):**
- **New build** (`adaptation_id is None`): mint a session UUID; send `message` with `--append-system-prompt <harness>` and `ADAPT_ALLOWED_TOOLS`, `new_session=True`. Yield an event carrying the new `adaptation_id` so the UI can add the rail row immediately.
- **Resume/edit** (`adaptation_id` given): read the record, `--resume claude_session_id`, inject the harness as `--append-system-prompt` (re-injected every turn — not sticky), `new_session=False`.
- **Manifest capture:** snapshot `git rev-parse HEAD` before the turn; after the stream ends, `git rev-list <prevHEAD>..HEAD`; for each new commit, `git show --name-only --format=` → map changed paths to surfaces (`scripts/workers/*.md`→worker[ref=path], `scripts/adapters/<fam>/<prov>.py`→adapter[ref=`fam/prov`], `cardtypes/registry.json`→card-type[ref=added cardType key(s), diff the registry]) and `adaptations_lib.add_artifact(...)` for each. When the build finishes and produced artifacts, flip state `building → off`.

After a turn that resulted in a successful ship (manifest grew), enqueue a follow-up `/compact` turn (send `compaction.compact_turn_message()` against the same session) — best-effort, swallow failures.
- **Persistence:** append every event to a per-adaptation event log (`datasets/adaptations/<id>.events.jsonl` via a small `adapt_transcript` helper, or reuse `chat_transcript` keyed by id). This is the log `live_runs.tail` replays.

**Endpoints (follow the existing `handle_chat` + `_sse_*` + `_route_request` patterns):**
- `POST /api/adapt` `{message, adaptation_id?}` → SSE. **Decoupled run:** if no live run for the key, `live_runs.start(key, adapt_runner.run_turn(adaptation_id, message), append_fn)`; then stream by `live_runs.tail(key, read_fn)`.
